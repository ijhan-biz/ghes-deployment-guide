GitHub Copilot 상황별 사용자 예산 설정

저장소 없이 Copilot만 쓰는 환경부터, 개인 증액과 부서별 비용 관리까지 필요한 상황에 맞는 방법을 선택하세요. 사용자별 총 소비 한도(Users)와 유료 지출 한도(Cost center · Org · Enterprise)는 역할이 다르므로 별도로 설정합니다.

00 · 요약 흐름도

상황별 설정 흐름도

좌석은 Copilot을 쓸 권한입니다. 크레딧은 채팅 등 일부 기능의 사용량을 세는 단위입니다. 어떤 권한과 한도가 필요한지 먼저 확인한 뒤, 해당 설정 절차를 보세요.

01 · 우선 적용저장소 미운영 환경

저장소 없이 Copilot Business만 사용

상황IDE에서 Copilot만 사용하고, 저장소나 Organization은 운영할 필요가 없습니다.

설정 방법: Enterprise 직접 할당과 기본 한도

좌석은 Enterprise Owner가 할당하고, 예산은 Enterprise Owner 또는 Billing Manager가 관리할 수 있습니다. 이미 회사 관리형 계정(EMU)을 쓴다면 Okta나 Entra ID 같은 신원 공급자(IdP)의 앱 할당과 로그인·계정 연동(SSO·SCIM)은 그대로 유지합니다.

  1. 플랜과 현재 라이선스 확인. Enterprise의 Billing and licensing → Licensing에서 Copilot Business 좌석과 Enterprise Cloud 소비 좌석을 별도로 확인합니다. 한 사용자가 GHEC Organization에 소속되면 저장소를 쓰지 않아도 Enterprise Cloud 라이선스를 소비할 수 있습니다.
  2. 직접 할당 사용자 정책 확인. 좌석을 배정하기 전에 AI controls → Copilot에서 Policies for enterprise-assigned users와 필요한 IDE·모델 접근을 확인합니다.
  3. 모든 사용자에 공통 한도가 필요하면 전사 기본 한도(Universal) 설정.Billing and licensing → Budgets and alerts → New budget → Bundled AI credits budget → Budget scope: Users → 사용자 선택란 비움 → 월 총 한도 → Create budget예를 들어 $30은 월 3,000 credits까지 허용한다는 뜻입니다. Business의 좌석당 월 포함량 1,900은 공유 풀에 더해지는 값입니다. 개인 상한을 일률적으로 $19로 잡으면 공유 풀이 남아도 1,900을 넘게 쓸 수 없습니다. 상한은 최근 실사용량과 승인된 정책에 맞춰 정합니다.
  4. 추가 사용료를 허용할지 결정. 좌석 배정과 사용 시작 전에 아래 두 가지 중 승인된 방식을 적용합니다.

추가 AI 사용료를 허용하지 않음

AI controls → Copilot → AI credits paid usage를 Disabled로 설정합니다. Business 공유 포함량은 적용된 사용자 한도 안에서 쓸 수 있지만, 소진 후에는 크레딧을 쓰는 기능이 차단됩니다. Users 범위의 $0은 공유 풀이 남아도 사용을 막으므로 이 목적에 쓰지 않습니다.

승인된 금액까지만 유료 사용 허용

AI credits paid usage를 허용하고, New budget → Bundled AI credits budget → Enterprise에서 승인된 유료 사용 상한을 입력한 뒤 Stop usage when budget limit is reached를 켭니다. 부서 한도와 중복 적용 여부를 확인한 후 테스트합니다.

  1. 좌석을 직접 할당하고 작동 확인.Billing and licensing → Licensing → Copilot → Manage → All members 또는 Enterprise Teams → Assign licensesEnterprise Team은 Organization의 팀과 다릅니다. 테스트 계정으로 좌석·IDE 로그인·채팅을 확인하고 Usage → AI usage에서 사용량을, Budgets and alerts에서 적용 한도를 확인합니다.

기존 Organization이 있다면: Copilot 직접 할당과 정상 사용을 먼저 검증합니다. Organization 자체를 정리할지는 저장소·권한과 업무 영향을 확인하고 별도로 승인받습니다. 예산을 변경하기 위해 조직·저장소나 Entra 계정을 삭제할 필요는 없습니다.

Bundled AI credits budget은 Copilot 외에도 사용 가능한 다른 AI-credit SKU를 포함합니다. 필요한 범위를 먼저 확인하고, 특정 SKU만 관리하려면 별도 SKU-level budget을 검토합니다. AI credits 예산은 좌석료·일반 Actions 사용료를 제한하지 않습니다. 예산 설정만으로 유료 비용을 선납하지 않으며, 새 지출 예산은 생성 전 발생한 비용을 없애지 않습니다.

02 · 개인 예외단일 사용자 한도 변경

특정 사용자만 월 사용 한도 조정

상황전사나 부서 기본값은 유지하고, 특정 사용자 한 명만 더 쓰게 하거나 한도를 낮추려는 경우입니다.

설정 방법: 개별 예산 생성 또는 수정

기존 개인 예산이 있으면 Budgets and alerts → 해당 항목의 … → Edit에서 수정합니다. 없으면 아래 경로로 만들고, 추가분이 아닌 월 총 사용 한도를 입력합니다.

가상 예시: 전사 기본 $19에서 한 사람만 $20 더 사용하게 하려면 개별 예산에 $39를 입력합니다. $19 + $39가 아니며, 공유 풀 잔량이 충분하면 월 3,900 credits 이내에서 추가 청구 없이 쓸 수도 있습니다. 유료 사용이 필요한 시점에는 별도의 정책과 지출 제한도 적용됩니다.

기간 제한: 이번 달만 증액한다면 개인 예산의 Expiration → End of current billing cycle을 선택합니다. 특정 날짜 지정도 가능합니다. 만료 후에는 적용 가능한 부서 또는 전사 기본 한도로 돌아갑니다. 둘 다 없으면 사용자 한도가 없어집니다.

사용자 증액 요청: 해당 비용을 부담하는 Enterprise/Organization 설정의 Requests from members에서 요청을 확인합니다. 내부 승인 후 새 총액을 입력하고 Approve and increase를 선택합니다. 다른 지출 제한에 걸려 있으면 개인 한도만 올려도 사용은 재개되지 않을 수 있습니다.

03 · 부서 통제Cost Center 설계

부서별 1인 한도와 총지출 관리

상황부서마다 1인당 사용 한도를 다르게 주고, 부서 전체의 유료 지출이나 포함 크레딧 사용량도 따로 제한하려는 경우입니다.

설정 방법: Cost Center에 필요한 한도만 추가

Cost Center는 사용량과 지출을 부서·프로젝트에 귀속시키는 단위입니다. Cost Center를 만드는 것만으로 비용이 제한되지는 않습니다. 한 팀의 1인당 상한, 팀 유료 지출, 팀의 공유 풀 사용 상한을 각각 결정합니다.

  1. 부서 Cost Center 생성. Enterprise → Billing and licensing → Cost centers → New cost center → Resources → 사용자 또는 Enterprise Team → Create cost center Copilot 전용으로 Organization에 소속되지 않은 사용자를 직접 등록하려면 Cost Center API 경로가 필요합니다. UI에서 관리할 때는 미소속 사용자를 포함하는 Enterprise Team을 Cost Center에 연결하고 실제 귀속을 확인합니다. Cost Center 등록은 Copilot 좌석 부여와 별개입니다.
  2. 이 부서의 1인당 한도 설정. New budget → Bundled AI credits budget → Users → Cost Center 선택. 가령 $40이라면 부서 전체 $40가 아니라 각각 월 4,000 credits입니다. 다른 Cost Center에 직접 배정된 사용자나 개인별 예외가 있는 사용자는 실제 적용값을 확인합니다.
  3. 부서 전체의 유료 지출 상한 설정. 같은 예산 유형에서 이번에는 Budget scope: Cost center를 선택하고 금액을 지정합니다. 예를 들어 유료 사용 상한을 $100으로 승인했다면 Stop usage when budget limit is reached를 켭니다. 전사 지출 상한과 그 부서 예산이 함께 적용되는지 확인합니다.
  4. 부서의 포함량도 분리할 때만 Included usage controls 설정. Cost centers → 해당 항목의 … → Edit에서 제공되는 포함 사용량 설정을 확인합니다. GitHub가 해당 Cost Center에 귀속된 라이선스 기준으로 상한을 계산합니다. 상한 도달 시 차단 또는 유료 사용 전환을 선택합니다. 전환을 선택해도 AI credits paid usage와 유효한 지출 한도를 충족해야 합니다. 기능이 안 보이면 해당 계정의 플랜·권한과 메뉴를 확인합니다.

특정 부서만 유료 허용: 개인별 예산만 높이는 것으로 유료 사용자를 선별할 수 없습니다. 허용 부서와 비허용 부서를 분리해 실제 비용 귀속을 확인하고, 비허용 범위에는 유료 지출 $0 + Stop을 적용합니다. 미귀속 사용자와 다른 겹치는 예산도 확인합니다. 전사 $0 한도가 부서에도 적용 중이면 유료 허용 부서도 막힙니다. 전사 예산의 Cost Center 제외 옵션을 쓰려면 영향받는 모든 Cost Center에 각각 승인된 지출 상한($0 포함)이 있는지 확인합니다.

직접 사용자 귀속이 팀 귀속보다 우선합니다. 사용자가 여러 Enterprise Team을 통해 서로 다른 Cost Center에 들어가면 공식 기준은 먼저 생성된 팀입니다. 기본적으로 부서 지출도 전사 예산에 반영됩니다. Exclude cost center usage from this budget을 켜면 그 전사 한도에서 Cost Center 사용량이 빠지므로 별도 승인 없이 켜지 않습니다.

04 · 플랜·조직 비교과금 시작점과 예산 산정

저장소 운영·Copilot access 전환 시 설정 차이

상황GHEC 저장소와 Organization도 운영하거나, Business에서 Copilot Enterprise 또는 Copilot access로 바꾸는 방안을 검토합니다.

Copilot access 전환: 2026년 11월 18일 확인한 공식 안내 기준, GitHub/Microsoft 계정팀을 통해 제공이 시작됐으며 셀프서비스는 아직 제공되지 않는다고 명시합니다. 전환은 선택 사항이며 같은 Enterprise에서 Business/Enterprise 좌석과 병행할 수 없습니다. 예전에 “Copilot 단독”이라고 부른 Business 구성은 새 Copilot Standalone과 다른 모델입니다. Copilot access에서 GHEC 라이선스가 사라지면 Copilot 좌석도 해제되며, 관리자가 비용을 승인하고 다시 할당하기 전에는 유료 Standalone으로 자동 전환되지 않습니다.

GHEC 저장소·Organization을 함께 운영한다면: 조직에 Copilot을 허용하는 것과 각 사용자에게 좌석을 주는 것은 다릅니다. 조직에 청구되는 Copilot 좌석 기준으로 Organization 예산을 두거나, 부서별로 안정적인 귀속이 필요하면 사용자 중심 Cost Center를 사용합니다. 같은 Enterprise의 여러 Organization이 한 사람에게 좌석을 주면 Copilot 비용은 사용자당 한 번이지만 배정 조직이 달라질 수 있으므로 조직 예산만으로 고정 귀속을 기대하지 않습니다.

비용 추정 예시 · 가상 데이터: Business 20석을 한 달 유지하고 하나의 풀을 쓰면, 정가 좌석료는 $380이고 포함 크레딧은 38,000($380 상당)입니다. 18명 $30·2명 $50의 개인 상한 합계는 $640입니다. 모두 한도까지 사용할 수 있다고 가정하면 포함량과의 차이는 $260입니다. 전사 유료 사용 상한을 $100으로 강제하면 해당 예산이 적용되는 지출은 $100에서 제한됩니다. 기존 비용·별도 SKU·예외·세금과 계약 조건은 이 단순 예시에 포함하지 않습니다.

05 · 운영 점검

포함 크레딧 상한과 좌석 수 불일치

가상 예시 · 모두 Copilot Business이며 월 전체 기준 1석당 1,900 credits로 단순 계산

화면에 표시된 상한

28,500 credits

월 15석분에 해당합니다. 화면값만으로 현재 15명이 좌석을 소비한다고 판단하지 않습니다.

현재 14석으로 계산한 예상 상한

26,600 credits

14 × 1,900입니다. 월중 변경 시점이나 좌석 귀속을 반영한 확정값은 아닙니다.

  1. 화면 기준 고정. Billing and licensing → Cost centers → 대상 → View details에서 AI credit pool enabled의 분자(사용량)와 분모(포함 사용 상한)를 기록합니다. 조회 시각·청구월·직접 사용자·연결된 Enterprise Team을 함께 확인합니다.
  2. 실제 좌석 대조. Licensing → Copilot → Manage 또는 라이선스 보고서에서 Business/Enterprise와 할당 경로를 대조합니다. 직접 할당, Enterprise Team, Organization으로 들어온 좌석을 사용자별로 중복 없이 확인합니다. Cost Center에 등록됐어도 좌석이 없으면 포함량을 만들지 않습니다.
  3. 변경 시점 대조. 좌석 추가·회수·플랜 변경 및 Cost Center 이동의 실제 적용 시각을 확인합니다. 공유 풀 리셋은 매월 1일 00:00 UTC(한국시간 09:00)입니다. 포함 상한 증가와 감소의 반영 시점이 다르므로 오늘의 등록 인원만 곱하지 않습니다.
  4. 보고서와 화면의 역할 구분. Usage → AI usage → Get usage report는 사용자 소비량을 보여주는 자료입니다. Cost Center의 설정 상한을 증명하는 별도 필드라고 가정하지 않습니다. 계속 차이가 나면 상한 캡처, 해당 월·변경 시각·좌석/귀속 이력으로 GitHub Support에 산정 기준을 확인합니다.

월중 변경: Business·Enterprise 신규 좌석료는 일할 계산되고 포함 크레딧도 일할 계산될 수 있습니다. 공유 풀의 증가는 바로 반영되지만, 좌석 회수에 따른 풀 감소와 Cost Center 포함 상한 감소는 다음 청구 주기에 반영됩니다. 포함량 제어를 적용한 Cost Center 간 이동의 상한 재계산도 다음 주기 기준입니다. 실제 불일치 원인은 좌석과 귀속 이력을 확인해야 알 수 있습니다.

변경할 설정 구분: 부서가 자체 좌석의 포함량까지만 쓰게 하려면 Included usage controls → 상한 도달 시 차단을 선택합니다. 구성원 각각의 월 한도는 Users → 해당 Cost Center에서 따로 설정합니다. 개인 예산 금액을 바꿔도 표시 상한의 산정 차이가 해결되지는 않습니다.

포함량 조정 규칙 · 월중 좌석과 크레딧

Copilot 외 Enterprise Cloud 비용 표시

  1. 소비 중인 좌석 확인. Billing and licensing → Licensing에서 Enterprise Cloud의 현재 소비 좌석과 당월 청구 대상 좌석을 구분합니다. 사용 중인 좌석이 0이어도 그 달에 이미 소비한 좌석은 청구 대상에 남을 수 있습니다.
  2. 일별 청구 내역 비교. Usage → Metered usage에서 Enterprise Cloud 항목의 날짜·수량·단가·청구 대상 금액을 확인합니다. 가상 예시로, 하루 내역이 10석 × $0.70 = $7.00이면 하루 $7은 10석 합계입니다. 과거 날짜의 내역이 보이는 것만으로 현재도 과금이 계속된다고 판단하지 않습니다.
  3. 청구 조정 결과 확인. 접수 계정으로 GitHub Support → My Tickets → 기존 티켓을 열어 처리 답변의 대상 기간·적용일·금액을 확인합니다. 답변이 없으면 기존 티켓에 최근 날짜의 내역을 추가합니다. Azure 결제라면 확정액은 발행된 Azure 청구서에서 확인합니다.

개인별 한도와 별개: Enterprise Cloud 좌석료는 Copilot의 AI 크레딧 사용료가 아닙니다. 개인별 예산이나 AI 크레딧 유료 지출 한도를 바꿔도 Enterprise Cloud 좌석료가 조정되지는 않습니다.

현재 소비와 당월 청구 대상 · 내역·청구서·티켓 조회

개인별 예산 편집 화면 오류

  1. 기존 예산을 유지. 개별 예산을 삭제하거나 $0으로 덮어쓰지 않습니다. 삭제하면 부서·전사 기본값이 적용될 수 있고, $0은 AI 크레딧을 쓰는 기능을 막습니다.
  2. 접속 범위와 권한 확인. 올바른 Enterprise와 관리자 역할을 확인하고, 시크릿/InPrivate 창 및 다른 권한 있는 계정에서 동일 항목을 열어 봅니다. 특정 항목만 실패하는지도 확인합니다.
  3. 필요하면 조회 후 문의. 지원되는 권한으로 Budgets REST API의 읽기 조회를 이용해 현재 적용 예산을 확인하고, 긴급 변경은 승인된 범위에서만 검토합니다. API가 정상이라고 가정하지 말고, 재현되면 오류 정보와 함께 GitHub Support에 문의합니다.

좌석 수·사용량·청구 금액 비교

상세 보고서의 날짜·제품 코드(SKU)·비용이 잡힌 부서(cost_center_name)·청구 대상 금액(net_amount)을 대조합니다. Azure 연결 시 확정액은 발행된 Azure 청구서에서 확인합니다.
